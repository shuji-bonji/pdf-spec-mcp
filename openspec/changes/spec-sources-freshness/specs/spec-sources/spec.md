## Purpose

pdf-spec-mcp が `PDF_SPEC_DIR` にある仕様書の PDF を、どの時点の内容で読むかを定めます。個々のツールの入力と出力は各ツールの capability に書き、ここには全ツールに共通する「仕様書の見つけ方と鮮度」だけを書きます。

## ADDED Requirements

### Requirement: SPEC-PDFSPEC-SPEC-SOURCES-001 仕様書の読み込みや索引作りに失敗した結果を覚えない

仕様書の読み込み・索引作り・`PDF_SPEC_DIR` の走査に失敗したとき、本サーバはその失敗をプロセスの中に覚えず、次の呼び出しでやり直す（SHALL）。成功した結果は、元の仕様書が変わらない間は使い回してよい。

#### Scenario: 節の索引を作るのに失敗した後で PDF を直すと、次の呼び出しで作り直す
- **WHEN** 1 回目の呼び出しで節の索引を作るのに失敗し、その後で仕様書の PDF が読める状態になってから、同じプロセスでもう一度呼ぶ
- **THEN** 2 回目は索引を作り直し、直した PDF から答える

#### Scenario: PDF_SPEC_DIR の走査に失敗した後でフォルダーを作ると、次の呼び出しで読む
- **WHEN** `PDF_SPEC_DIR` のフォルダーが無い状態で 1 回目の走査が失敗し、その後でフォルダーと仕様書を置いてから、もう一度走査を求める
- **THEN** 2 回目は走査をやり直し、置いた仕様書を見つける

### Requirement: SPEC-PDFSPEC-SPEC-SOURCES-002 差し替えた仕様書を、次の呼び出しで差し替えた後の内容から読む

起動している間に `PDF_SPEC_DIR` の仕様書の PDF が差し替えられたとき（大きさか更新時刻が変わったとき）、本サーバは次の呼び出しで、その仕様について覚えている索引・節の本文・読み込んだ文書を捨て、差し替えた後の PDF から答える（SHALL）。仕様書が変わらない間は、作った索引を使い回す（SHALL）。

#### Scenario: 仕様書を差し替えると、次の呼び出しで差し替えた後の内容から答える
- **WHEN** 1 回目の呼び出しの後で、同じ名前の仕様書を別の PDF に差し替え、同じプロセスでもう一度呼ぶ
- **THEN** 2 回目は文書を読み直し、差し替えた後の PDF の内容を返す

#### Scenario: 仕様書が変わらなければ、2 回目は読み直さない
- **WHEN** 仕様書を変えずに、同じプロセスで同じ呼び出しを 2 回する
- **THEN** 文書の読み込みは 1 回だけで、2 回目は同じ内容を返す

### Requirement: SPEC-PDFSPEC-SPEC-SOURCES-003 PDF_SPEC_DIR に足した・消した仕様書を、次の呼び出しで見る

起動している間に `PDF_SPEC_DIR` に仕様書が足された・消された・名前が変わったとき、本サーバは次の呼び出しで、その変化を仕様書の一覧と仕様の ID の解決に反映する（SHALL）。見つからない仕様の ID に `retryable: true` を返す以上、仕様書を置いた後の再試行で結果が変わらなければならない。

#### Scenario: 足した仕様書が、次の呼び出しで一覧に出て引ける
- **WHEN** 1 回目の走査の後で `PDF_SPEC_DIR` に仕様書を足し、もう一度走査を求める
- **THEN** 足した仕様書が一覧に出て、その仕様の ID でパスを引ける

#### Scenario: 消した仕様書は、次の呼び出しで一覧から消える
- **WHEN** 1 回目の走査の後で `PDF_SPEC_DIR` から仕様書を消し、もう一度走査を求める
- **THEN** 消した仕様書は一覧に無く、その仕様の ID は見つからないと答える
